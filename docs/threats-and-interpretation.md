# Threats and interpretation

## Construct boundary

The optimized object is a weighted union of declared origins supporting two opposed fixed-Horn derivations. It is not a bug cause, patch, minimum inconsistent source program, or human debugging effort. Weights are analyst-supplied. The three retained profiles demonstrate objective sensitivity but do not validate a cognitive cost model.

Strong negation records incompatibility inside the declared belief language; it does not determine which belief is false. Fixed positive rules make the selection predicate monotone. Re-estimating a rule from a selected population is deliberately analyzed as a different predicate.

## Internal validity

Implementation errors are possible despite written proofs. Risk is reduced through 35 tests, 825 exact/oracle comparisons using a distinct bit-mask representation, formula families, a separate consumer, and mutation tests. The producer and consumer were developed in one research process, so this is not an independent replication. The proofs are ordinary mathematical arguments, not proof-assistant objects.

The deterministic random generator is a coverage instrument, not a model of real analyses. Its zero discrepancy count supports regression and finite differential correctness only. It must not be translated into an error probability for unseen repositories.

## Public-source interpretation

The cJSON, inih, and mjson excerpts preserve exact tagged text and matching license notices. Their changes exercise source paths, anchors, two-snapshot endpoints, bridges, sharing, and weights. The surrounding belief graphs are controlled seeds. No maintainer asserted those beliefs, and no experiment executes the C code. Therefore the study does not measure defect discovery, causality, or semantic equivalence.

Packaging excerpts rather than whole repositories omits build flags, preprocessor state, generated code, aliases, and surrounding control/data flow. That is acceptable for anchor replay but insufficient for an end-to-end static-analysis claim.

## External validity

The language is finite, ground, and positive. Real analyzers may use variables, paths, numeric domains, aliasing, concurrency, and nonmonotone learning. Grounding those analyses may create much larger antichains. The NP-completeness result is a worst-case boundary; the scaling experiment is a constructed pair-count study and not a repository-throughput forecast.

Version identity is explicit. Renames, splits, merges, refactorings, configuration variants, and generated artifacts need richer bridge evidence. Equal names are intentionally insufficient.

## Reproducibility meaning

Byte-identical deterministic outputs establish that the packaged finite computation regenerates. Timing and logs can vary. Source-anchor replay establishes retained textual identity, not semantic continuity. A successful command does not certify novelty, theorem truth, external policy compliance, or acceptance.

## Responsible use

The executable experiments use deterministic conventional Python and make no external model calls.
